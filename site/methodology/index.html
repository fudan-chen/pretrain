METHODOLOGY · marin-matched-progress-v1

每一个预测，都要能从零复算。

当前实现忠实对应 Marin 固定 commit d23e6e9c 的 per-5% 方法，并额外报告 leave-one-rung-out 敏感性范围。

01 / QUESTION

到底在拟合什么？

在每一个相同训练百分位 g 上，取 d768、d1024、d1536、d2048 四个 rung 的 Paloma loss 与同百分位 compute，拟合：

log(L − 1.5) = log(Ag) − αg · log(C)

再把同百分位的 Hero compute 代入。于是每个 5% 都有自己的一组 A_g / alpha_g；这是一组横截面 fits，不是一条由终点系数生成的纵向学习曲线。

02 / FIXTURES

Compute 统一为 training FLOPs excluding lm_head；Hero terminal compute 为官方脚本中的 2.6108941613772703e24，而不是未解释口径的 2.70e24。

03 / BETWEEN GRID POINTS

非 5% eval 如何比较

step 47,999 对应 8.45584%。v2 不插值 A/alpha，只在 5% 与 10% 两个 Hero 点预测之间对 loss 线性插值：

prediction(8.45584%) = 2.30823
residual = 2.26195 − 2.30823 = -0.04628

5% 之前返回 unavailable，100% 之后返回越界；不会静默外推。

04 / UNCERTAINTY

敏感性范围不等于置信区间

当前对四个 rung 逐一 leave-one-out，得到一个方法敏感性 envelope。它能揭示单个 rung 对外推的影响，但不提供统计覆盖率，因此页面禁止自动写“显著领先”。

  • 允许：实测低于点预测 0.04628
  • 允许：LOO residual range [-0.05847, -0.04066]
  • 不允许：已显著领先
  • 不允许：保证终点达到 2.04

05 / RAW EVIDENCE

先追到 rung 原始记录，再谈复现

普通 build 从已固定的本地证据离线复算。若要审查 grid 的来源，需显式运行网络采集器；它保存四个 rung 的 JSONL、run ID、metric key、采集时间、归一化规则与 checksum。

python scripts/collect_ladder_grid.py
python scripts/track_hero.py build

证据链是：W&B sampled history → rung JSONL → 5% grid + manifest → baseline → current status → typed Claim。采集被明确标为 server-sampled，不冒充完整逐步历史。

06 / BUILD & FALSIFY

重建之后，还要主动让结论失败

python scripts/track_hero.py build
python -m unittest discover -s tests -v
python scripts/audit_v2.py --context-length 8192

context 或 datamix 不匹配时，baseline applicability gate 会抑制 comparison；residual 方向翻转时，解释文案必须同步翻转。进入反证实验室 →
